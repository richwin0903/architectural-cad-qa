# 用 CAD 问答项目学习 AI 应用

目标是能独立运行、解释、修改和验证一条完整业务链路。仓库是基于开源项目的二次开发，
作品集应说明上游来源、自己负责的部分、验证方法和仍存在的局限。

## 建议的四个阶段

1. **跑通并解释**：完成安全配置、上传合成图纸、提问和依据定位；画出从浏览器到模型的请求链路，
   解释哪些计算由确定性工具完成、哪些文本由模型组织。
2. **独立实现一项变化**：选择图层筛选、查询体验、错误提示或一个新的只读工具；先定义验收条件，
   再提交自己的实现和有区分力的测试。保留真实 Git 提交和设计取舍。
3. **建立评测**：为可再分发的图纸整理已知答案，记录图块计数、单位换算、引用正确性、失败类型、
   延迟和模型用量。按图纸划分开发集与测试集，避免同图近似问题泄漏。
4. **交付和答辩**：在自己的环境部署，录制演示，复盘一次失败案例；能解释鉴权、数据去向、
   DWG 转换限制、模型超时以及费用控制方案。

## 方向不同，增加的工作也不同

| 方向 | 适合补充的工作 | 应交付的证据 |
| --- | --- | --- |
| AI 应用开发 | 工具调用、异常恢复、证据校验、部署与鉴权 | 可运行版本、测试、接口说明、故障复盘 |
| AI 产品 | 访谈、任务流程、试用引导、反馈与成本设计 | 访谈记录、PRD、原型、指标定义与实测结果 |
| AI 算法 | 文本/属性检索基线、向量检索与重排对比、查询路由实验 | 有许可的数据集、数据划分、基线、消融与错误分析 |

现有 API 集成不等于完成了算法研究。算法方向应先定义任务与基线，数据规模和误差分析支持时
再考虑微调；不要为了增加技术名词而引入没有验证价值的模型训练。

## 可以诚实写进作品集的内容

描述具体贡献，例如“在开源 CAD 解析基础上实现中文只读问答与图元引用校验，并用 N 张合成/授权
图纸的 M 个问题验证计数与定位”。N、M、准确率、延迟和费用都应来自自己的实际记录。

把教学项目标为个人项目或课程项目；团队协作时说明分工。不要虚构企业客户、上线用户量、
商业收入、原创模型训练或未做过的工程职责。

## 可用于检查理解的问题

- 为什么不让模型直接估计门数量和面积？图块实例与真实构件数量有什么区别？
- 引用不存在的图元时系统如何处理？引用正确是否意味着答案一定正确？
- DWG 转换丢失代理对象后，为什么不能把预览当成原图的完整表达？
- 为什么后端不公开编辑接口？为什么前端隐藏按钮不能代替鉴权？
- 如何定义一个可重复的检索实验，避免图纸之间的数据泄漏？
- 如果要向公众发放试用账号，还缺哪些隔离、撤销、额度和费用控制？
