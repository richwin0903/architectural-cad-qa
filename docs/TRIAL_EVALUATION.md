# 试用排队、反馈与费用

默认 2 个问答并发、8 个等待位置、最多等待 90 秒。浏览器显示自己的排队位置，自动等待服务器开始处理，
不会因一次“忙”就反复重发 POST。排队不扣额度，开始处理前再次验证登录、图纸归属和剩余额度。
同一账号不能重复占位；请求 ID 防止重复执行。队列满、等待超时、排队中退出/过期均不会调用模型。
问答处理超时仍为 180 秒；浏览器 300 秒、代理 330 秒留出排队余量。服务重启会结束内存中的等待请求。
渲染器仍串行保护 Matplotlib；2 并发允许模型等待与其他处理重叠，不代表首问耗时减半。

## 数据记录

登录页、使用指南和提问区共用 `qaPrivacy.js`，告知整图/局部截图与结构化图元及对话将发送至 DeepSeek。
本站另保存 30 天的评估记录：账号、问题文本、创建时间、排队/处理耗时、HTTP 成败、模型报告的 token 数、
有用/没用反馈。问题属于可能敏感的业务数据；记录不包含 CAD 文件、截图、完整答案、历史对话或配置密钥。
数据库位于 `CAD_AUTH_DB` 同目录的 `qa-events.sqlite3`，权限 600；每 5 分钟清理过期行，重启会标记未完成记录。
退出不删除评估记录，但立即撤销图纸及反馈访问。用户只能评价本次登录产生的成功回答，重复提交只更新一条反馈。

汇总只计算试用账号，避免管理员自己测试混入真实用户指标；临时验收记录发布时会单独清除。
请求成功率表示技术完成情况，“有用率”只统计已反馈的回答，两者都不是准确率。
没有保存完整答案，所以无法从这些记录重建完整问答；若要发布案例，应另行征得用户授权并保留脱敏材料。

## 管理员查看

在服务器使用容器管理权限执行（容器名按实际部署调整）：

```bash
docker exec cad-qa-app-1 python -m web.backend.qa_analytics
```

默认只输出汇总：试用账号数、请求数、完成/成功数、反馈数量与有用率、平均排队/处理耗时、已报告 token 总数。
没有公网统计接口，试用账号不能查看其他人的记录。

需要私下复盘问题时导出到受保护文件（拒绝覆盖已有文件）：

```bash
docker exec cad-qa-app-1 python -m web.backend.qa_analytics --questions --output /data/trial-review.json
```

明细不会打印到终端；通过受保护方式取回，别提交到 Git、公开帖子或普通日志。
导出文件与管理员创建的备份不由 30 天在线清理任务管理，请按相同保留期限手动删除。

## 费用控制

10 个账号 × 累计 30 次 = 最多 300 次试用问答请求；管理员请求不计入此数。
每次 Agent 请求可能多次调用模型（目前最多 6 轮），图像、上下文长度与缓存命中也影响费用。
不要直接把“一个简单问题的一次 API 费用 × 300”当作可靠上限。

建议为试用使用可独立限制预算的供应商项目或账户，并在受保护运行时配置中更换 key。
单独创建一个 key 便于归因，但若多个 key 共享同一账户余额，就没有独立金额上限。
更换 key 时只编辑 `.secrets/runtime.env`（本仓库部署）或服务器现有受保护配置，再重建应用容器。
不把 key 放进聊天、命令参数、前端或仓库。本站当前仍没有按金额的费用熔断。

新增记录的 token 是模型已返回的报告值；失败调用可能没有用量数据，缓存价格也可能不同。
预算应以专用试用范围的真实账单为准；历史未记录的调用无法从本站补算准确花费。
